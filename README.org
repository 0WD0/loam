#+title: Loam

Loam 是一个基于 EDN 的 Org 语义站点框架。

它读取结构化 EDN 文档，通常由 =ox-edn= 从 Org 文件导出，然后生成带索引、链接解析、反向链接、搜索、图谱数据和可扩展渲染能力的静态站点。

Loam 的核心立场是：Org 已经有丰富语义，站点生成器不应该先把它压扁成 Markdown 风格的中间模型。=ox-edn= 负责把 Org 导出成语义 EDN；Loam 负责路由、索引、渲染、资产和交互。

* 设计目标

- 语义优先：保留 Org 的 ID、CUSTOM_ID、target、radio target、fuzzy link、headline 层级和 src block
- EDN 原生：不经过 Markdown 转换层，每一阶段都是可检查的 Clojure 数据
- 静态优先：默认输出纯静态文件，可以部署到任意静态服务
- 可扩展：渲染器、索引器、布局、head 注入、hook 和静态资产都可以替换
- 小核心：Loam 不试图拥有完整前端框架；交互能力通过扩展和编译资产加入
- 与 =ox-edn= 分工清晰：=ox-edn= 只导出语义数据，Loam 只处理站点层能力

* 快速开始

先安装 Node 依赖。Node 依赖用于运行测试、编译 Loam 浏览器端客户端，并提供 Shiki 相关前端开发入口。

#+begin_src bash
npm install
#+end_src

运行测试：

#+begin_src bash
npm test
#+end_src

从 EDN 目录构建静态站点：

#+begin_src bash
npm run build -- \
  --edn-dir /path/to/edn \
  --output-dir build/site \
  --url-prefix /notes/
#+end_src

也可以用配置文件：

#+begin_src bash
cp loam.edn.example loam.edn
bb build --config loam.edn
#+end_src

本地预览：

#+begin_src bash
npm run serve
#+end_src

如果使用相邻的 =ox-edn= 项目，可以直接指向它生成的 EDN 目录：

#+begin_src bash
npm run build -- \
  --edn-dir /home/disk/Projects/ox-edn/build/edn \
  --output-dir build/site \
  --url-prefix /notes/

npm run serve
#+end_src

注意：默认高亮 provider 是 Shiki。若显式启用 Tree-sitter WASM，高亮需要通过 HTTP 服务访问。不要直接用浏览器打开 =file://.../index.html= ，否则浏览器通常会阻止 =fetch= / WASM / ESM 资源加载。

* Docs compiler：Envelope v1 → Starlight Manifest v1

=loam.emit.starlight= 是独立于默认 Loam 站点构建器的严格 docs compiler 边界。它读取 ox-edn Envelope v1，用 envelope 中的仓库相对路径读取并校验真实 Org 源文件，执行 =load → validate → normalize → partition → index → resolve → render → emit=，然后原子替换完整输出 generation。

在一个 jj workspace 中运行：

#+begin_src bash
npm run docs:compile -- \
  --repo-root /path/to/majutsu \
  --output-dir /path/to/majutsu/.cache/majutsu-docs \
  --commit-id COMMIT \
  /path/to/ox-edn-output/index.edn \
  /path/to/ox-edn-output/majutsu.edn
#+end_src

CLI 要求调用方显式传入 =--commit-id=，Loam 不探测或调用任何版本控制工具。可选的 =--base=、=--version= 和 =--locale= 控制最终 route。成功输出包含 =manifest.json=、=build-report.json= 与 =pages/*.html=；blocking error 不发布新 generation，defer warning 会把 manifest/report 标为 =unreleasable=true=。

Clojure 调用边界是 =loam.emit.starlight/compile-envelope-files!=：

#+begin_src clojure
(require '[loam.emit.starlight :as starlight])

(starlight/compile-envelope-files!
 "/path/to/majutsu"
 ["/path/to/ox-edn-output/majutsu.edn"]
 {:output-dir "/path/to/majutsu/.cache/majutsu-docs"
  :build {:commitId "..."}})
#+end_src

Envelope fixture、golden HTML fragment 与原子替换回归测试分别位于 =test/fixtures/consumer-envelope-v1.edn=、=test/fixtures/golden/minimal-fragment.edn= 和 =test/loam/emit_starlight_test.clj=。Manifest 只公开仓库相对 source path；本机绝对路径会令编译失败。

* 数据流

Loam 的默认数据流如下：

#+begin_example
Org 文件
  │
  ▼
ox-edn
  │  导出语义 EDN
  ▼
*.edn 文档目录
  │
  ▼
loam.site/build-site!
  │
  ├─ 读取文档
  ├─ 建立页面索引、标题索引、ID/custom-id/target 索引
  ├─ 解析链接、反向链接、搜索数据和图谱数据
  ├─ 渲染 HTML
  ├─ 写入扩展资产
  └─ 复制 public/ 静态文件
  ▼
静态站点目录
#+end_example

这个分层让 Loam 可以在不理解 Org 解析细节的情况下工作。Org 语义由 =ox-edn= 保留，Loam 只消费稳定的数据结构。

* 当前静态输出

默认构建会输出：

- =index.html=：首页，包含分组侧边栏和搜索框
- =notes/<slug>/index.html=：每个 EDN 文档对应一个页面
- =index.edn=：公开的导航、文件夹分组、标题目录、链接、反链、搜索、图谱索引数据
- =search-index.json=：浏览器搜索使用的 JSON 数据
- =graph.edn= 和 =graph.json=：图谱节点和边
- =assets/site.css= 和 =assets/search.js=：默认主题资产
- =assets/loam-shiki.css= 和 =assets/loam-shiki.js=：默认 Shiki 高亮资产
- =assets/loam-client.js=：由 =shadow-cljs= 编译的 Loam 浏览器端客户端
- 如果启用 Tree-sitter：还会输出 =assets/loam-treesitter.css=、=assets/loam-treesitter.json=、=assets/tree-sitter/loam-runtime.js=，并需要 =assets/tree-sitter/**= 运行时资产
- =public/**=：用户静态文件，构建时复制到输出目录根部

文件夹分组由 =loam.directory= 扩展建立。页面侧边栏会消费 =:directories= 索引并按 EDN 相对目录分组。例如 =daily/*.edn= 会出现在 =daily= 分组下，根目录文档会出现在默认 =notes= 分组下。

页面内标题目录由 =loam.toc= 扩展建立。默认 theme 会在正文前渲染当前页面的 headline 层级目录。

* 目录和资产约定

Loam 的静态资产有两类：

1. 用户资产：放在 =public/= 下，构建时原样复制到输出目录。
2. 扩展资产：由 extension 贡献到 =:assets= target 的 map 生成，构建时写入输出目录。

默认构建顺序是先复制 =public/=，再写入 extension 资产。因此如果两者写入同一路径，extension 资产会覆盖 =public/= 中的文件。建议用户资产和扩展资产使用不同路径，避免无意覆盖。

Tree-sitter WASM 资产不手动提交到仓库。它们由 Guix 固定 runtime、CLI、grammar 源码和 WASI SDK，再由脚本同步到 =public/assets/tree-sitter=：

#+begin_src bash
npm run copy-tree-sitter-assets
npm run smoke-tree-sitter-assets
#+end_src

如果已经有外部构建好的资产目录，可以跳过 Guix build：

#+begin_src bash
LOAM_TREE_SITTER_ASSETS=/path/to/assets/tree-sitter npm run copy-tree-sitter-assets
#+end_src

Loam 的浏览器端客户端由 =shadow-cljs= 编译到 =public/assets/loam-client.js=：

#+begin_src bash
npm run client:release
#+end_src

通常直接运行：

#+begin_src bash
npm run prepare-assets
#+end_src

=public/assets/tree-sitter/= 和 =public/assets/loam-client.js= 是生成物，已经在 =.gitignore= 中忽略。

* 声明式 Web System

Loam 可以被理解成一个声明式 Web system，而不只是模板渲染器。如果把一个 Web 应用类比成操作系统，那么 Loam 的 system map 就类似系统配置：它声明内容如何被读取、索引、渲染、布局、注入 head、写入资产，以及构建完成后触发哪些 hook。

这个类比受 Guix 启发，但不是直接照搬。Guix 的核心不是给 service 写一张 =conflicts= 表，而是把 service type 组织成 DAG：service type 声明它扩展哪些 target service type；可扩展的 service type 声明 =compose= 和 =extend=，由 =fold-services= 把 extension 沿图传播到 root service。若 extension 找不到唯一 target，Guix 会报 missing / ambiguous target；profile/package 的文件碰撞则是另一层问题。

| Loam 概念 | Guix 启发 | 说明 |
|-----------+-----------+------|
| =loam.defaults/create-system= | system 配置入口 | 组合默认能力和用户配置 |
| EDN AST | 声明式源数据 | 由 =ox-edn= 从 Org 语义导出 |
| extension | service contribution | 向 renderer、indexer、layout、asset、head、hook 等槽位贡献值 |
| =:renderers= / =:indexers= / =:layouts= | extension target | 每个 target 都有自己的 compose/extend 规则 |
| =:highlight= | service variant / 单实例槽位 | 在 Tree-sitter、Shiki、none 或自定义 provider 之间选择 |
| =public/=、npm 资源、Guix Tree-sitter 资产 | 外部输入 / store 内容 | 作为静态构建的资源输入 |
| =build-site!= | build derivation | 从 system 和 EDN 输入生成一个静态输出目录 |
| =output-dir= | generation | 一个可以部署、回滚或比较的构建结果 |

这个方向带来几个架构原则：

- 声明优先：用户描述想要的 system，而不是在构建过程中到处手动改状态
- target 明确：extension 应该声明自己贡献到哪个能力槽位，而不是让全局 map 隐式抢 key
- 组合可定义：每类能力应该有自己的 compose/extend 规则，例如 append、merge、replace 或 error
- 单实例显式：像高亮 provider 这种互斥能力，应建模成单实例槽位或 variant，而不是靠安装顺序碰运气
- 资产可追踪：npm、Guix、WASM、CSS、JS 都应该能从声明追到输出路径
- 输出可复现：同一份 EDN 输入和同一个 system，应该生成可解释、可比较的静态站点

因此 Loam 的长期方向不是变成大型前端框架，而是成为 Org/EDN 驱动的声明式 Web system 构建层。

* 架构

Loam 被拆成小的、可替换的层：

| Namespace | 责任 |
|-----------+------|
| =loam.core= | service target、extension folding、hook 触发 |
| =loam.ast= | AST 遍历、标题提取、文本提取、source helper |
| =loam.anchor= | 统一 anchor / id 生成 |
| =loam.index= | 页面、标题、ID、CUSTOM_ID、target、链接和反链索引 |
| =loam.route= | URL 和输出路径转换 |
| =loam.render= | 基于 registry 的 AST -> Hiccup 渲染 |
| =loam.html= | 最小 Hiccup -> HTML 序列化 |
| =loam.json= | 最小 JSON 序列化 |
| =loam.search= | 搜索索引扩展 |
| =loam.graph= | 图谱数据扩展 |
| =loam.directory= | 文件夹分组索引扩展，把页面按 EDN 相对目录分组 |
| =loam.toc= | 标题目录扩展，为每个页面建立 headline 层级目录 |
| =loam.head= | extension 注入 =<head>= 的辅助函数 |
| =loam.theme.default= | 默认布局、分组侧边栏、搜索 UI、主题 CSS/JS |
| =loam.highlight.treesitter.wasm= | src block Tree-sitter WASM 高亮扩展 |
| =loam.highlight.shiki= | src block Shiki 高亮扩展 |
| =loam.client= | Loam 浏览器端客户端入口，使用 =shadow-cljs= 编译 |
| =loam.highlight.treesitter.client= | Tree-sitter 高亮客户端模块，由 =loam.client= 引入 |
| =loam.site= | 静态站点构建器和 CLI 入口 |

最重要的设计点：渲染不是一个框架内部封闭的巨大 =case=。渲染器是 extension 贡献到 =:renderers= target 后得到的 registry：

#+begin_src clojure
(:renderers system)
;; => {:paragraph fn, :headline fn, :link fn, ...}
#+end_src

因此 extension 可以只向 =:renderers= 贡献一个节点类型，而不需要 fork 整个渲染器。

* System 和 Extension

Loam 的运行配置叫 system。默认系统由 =loam.defaults/create-system= 创建，它会安装默认渲染器、高亮 provider、搜索、图谱、文件夹分组、标题目录和默认主题。默认高亮 provider 是 Shiki；Tree-sitter WASM 是显式 opt-in。

#+begin_src clojure
(require '[loam.defaults :as loam])

(def system
  (loam/create-system {}))
#+end_src

Extension 是普通 Clojure map，但能力不再直接摊在顶层，而是放在 =:extends= 里，明确贡献到哪个 service target。旧式顶层 =:renderers= / =:inline-types= / =:indexers= / =:layouts= / =:assets= / =:head= / =:hooks= 不再支持：

#+begin_src clojure
{:id :my/theme
 :extends
 {:renderers {:paragraph (fn [ctx node] ...)}
  :inline-types #{:my-inline-node}
  :indexers [(fn [index documents] ...)]
  :layouts {:page (fn [ctx document] ...)}
  :assets {"assets/theme.css" "body { ... }"}
  :head [(fn [ctx current-url]
           [[:link {:rel "stylesheet" :href "/assets/theme.css"}]])]
  :hooks {:site/built [(fn [event] event)]}}}
#+end_src

常见 extension key：

| Key | 说明 |
|-----+------|
| =:id= | extension 标识，方便调试和检查 folding 顺序 |
| =:extends= | target -> contribution 的 map |

内置 service target：

| Target | compose/extend 规则 | 说明 |
|--------+-------------------+------|
| =:renderers= | map merge | AST 节点类型到渲染函数；后者覆盖同名 key |
| =:inline-types= | set union | 哪些 AST 节点属于 inline 节点 |
| =:indexers= | vector append | 在构建索引阶段追加 indexer |
| =:layouts= | map merge | 页面布局函数，例如 =:page= 和 =:home= |
| =:assets= | map merge | 构建时写入输出目录的文本资产 |
| =:head= | vector append | 注入页面 =<head>= 的 Hiccup 或函数 |
| =:hooks= | event key merge + append | 构建阶段 hook，例如 =:site/built= |

安装 extension：

#+begin_src clojure
(require '[loam.defaults :as loam])

(def system
  (loam/create-system
   {:extensions [my-extension]}))
#+end_src

Extension 按顺序 fold。每个 target 自己决定如何 compose/extend：例如 =:indexers= 追加，=:renderers= 和 =:layouts= merge，后面的同名 key 覆盖前面的值。

* 高亮 Provider 选择

默认系统只会安装一个内置高亮 provider，避免 Tree-sitter 和 Shiki 同时争抢 =:src-block=。

#+begin_src clojure
(require '[loam.defaults :as loam])

;; 默认：Shiki
(loam/create-system {})

;; 显式使用 Tree-sitter
(loam/create-system {:highlight :treesitter})

;; 配置 Shiki
(loam/create-system
 {:highlight {:provider :shiki
              :theme "github-dark"
              :languages ["clojure" "javascript" "typescript" "python"]}})

;; 自定义 Tree-sitter 配置
(loam/create-system
 {:highlight {:provider :treesitter
              :languages {:clojure {:aliases ["clj" "cljs" "cljc" "edn"]
                                     :wasm "/assets/tree-sitter/languages/tree-sitter-clojure.wasm"
                                     :query "/assets/tree-sitter/queries/clojure/highlights.scm"}}}})

;; 不安装默认高亮
(loam/create-system {:highlight :none})
#+end_src

=:highlight= 支持这些值：

| 值 | 说明 |
|----+------|
| =:treesitter= | 使用默认 Tree-sitter WASM provider |
| =:shiki= | 使用默认 Shiki provider |
| ={:provider :treesitter ...}= | 使用 Tree-sitter，并传入 provider 参数 |
| ={:provider :shiki ...}= | 使用 Shiki，并传入 provider 参数 |
| =:none= 或 =false= | 不安装内置高亮 provider |
| extension map | 直接使用一个自定义高亮 extension |

如果你想用自定义高亮 extension，可以直接把它放到 =:highlight= 里，或者把 =:highlight= 设为 =:none= 后自己安装相关扩展。

* 文件夹分组扩展

侧边栏的文件夹分组不是 theme 里的硬编码逻辑，而是一个普通 index extension：

#+begin_src clojure
(require '[loam.directory :as directory])

(def system
  (loam/create-system
   {:extensions [directory/extension]}))
#+end_src

默认系统已经安装 =loam.directory/extension=。它会读取页面的 =:source-dir=，在 index 中写入 =:directories=：

#+begin_src clojure
[{:path "notes"
  :title "notes"
  :page-count 1
  :pages [...]}
 {:path "daily"
  :title "daily"
  :page-count 3
  :pages [...]}]
#+end_src

默认 theme 的侧边栏只消费这个文件夹分组索引；如果以后要做目录页、目录 RSS、目录权限或目录级配置，可以继续扩展 =loam.directory=，不用污染 theme。

* 标题目录扩展

标题目录是另一个普通 index extension：

#+begin_src clojure
(require '[loam.toc :as toc])

(def system
  (loam/create-system
   {:extensions [toc/extension]}))
#+end_src

默认系统已经安装 =loam.toc/extension=。它会读取每个页面的 =headline= 层级，在 index 中写入 =:toc=：

#+begin_src clojure
{"/path/to/page.edn"
 [{:level 1
   :title "Intro"
   :href "/notes/page#intro"
   :anchor-id "intro"
   :children [{:level 2
               :title "Install"
               :href "/notes/page#install"
               :anchor-id "install"
               :children []}]}]}
#+end_src

默认 theme 会在页面正文前渲染当前页面的标题目录。目录链接使用 Loam 统一 anchor 规则，因此和实际 headline HTML id 保持一致。

* 前端扩展和 npm 生态

Loam 的前端扩展不应该只服务 Tree-sitter。Tree-sitter 只是第一个需要浏览器端代码、WASM 和外部资产流水线的内置扩展。更通用的模型是：

- Clojure/EDN 层 extension 通过 =:extends= 贡献语义渲染、索引、布局、head 注入和 manifest
- npm 生态负责浏览器端开发工具、Shiki 这类 JS 包、UI 小组件、搜索库、图谱可视化库
- Guix 负责 Tree-sitter runtime/CLI/grammar 源码/WASI SDK/WASM 资产的可复现构建
- =shadow-cljs= 负责编译 Loam 自带的浏览器端入口
- =public/= 负责承载外部同步出来的静态资源和用户自定义资源
- =:head= target 负责把编译产物或 ESM loader 注入页面

现在 Loam 有一个通用浏览器入口：

#+begin_example
src/loam/client.cljs
#+end_example

它会被编译成：

#+begin_example
public/assets/loam-client.js
#+end_example

Tree-sitter 高亮是被 =loam.client= 引入的一个客户端模块：

#+begin_example
src/loam/highlight/treesitter/client.cljs
#+end_example

Shiki 高亮则使用 extension 生成的独立 ESM loader，因此不用把较大的主题/语言 runtime 强行打进 =loam-client.js=。

未来如果新增前端扩展，例如 Graph 交互、全文搜索 UI、代码复制按钮、图片灯箱、脚注 hover preview，可以把对应 CLJS namespace 加到 =loam.client=，并在该 namespace 中直接使用 npm 包：

#+begin_src clojure
(ns loam.client.my-widget
  (:require ["some-npm-package" :as widget]))
#+end_src

如果某个扩展更适合直接使用 ESM，而不是打进 =loam-client.js=，也可以像 Tree-sitter runtime loader 一样，由 extension 生成一个小的 =type="module"= loader，再通过 =:head= 注入。

因此当前约定是：Loam 内置交互走通用 =loam-client.js=；较大的第三方 ESM/WASM runtime 可以保持为独立静态资产。这样既能使用 npm 生态，又不会把所有 runtime 都强行塞进一个 bundle。

* Tree-sitter WASM 高亮

Tree-sitter WASM 高亮是 opt-in provider。它适合需要语法树语义、可定制 query 或较新/custom grammar 的站点；默认系统使用 Shiki 以避免普通构建依赖 Guix/WASM 资产。

如果你构建自定义系统，可以用 =:highlight= 显式配置 Tree-sitter：

#+begin_src clojure
(require '[loam.defaults :as loam])

(def system
  (loam/create-system
   {:highlight
    {:provider :treesitter
     :languages
     {:clojure {:aliases ["clj" "cljs" "cljc" "edn"]
                :wasm "/assets/tree-sitter/languages/tree-sitter-clojure.wasm"
                :query "/assets/tree-sitter/queries/clojure/highlights.scm"}}}}))
#+end_src

该扩展会：

- 覆盖 =:src-block= 渲染，添加 =data-loam-treesitter= 标记
- 写入 =assets/loam-treesitter.css=
- 写入 =assets/loam-treesitter.json= 语言 manifest
- 写入 =assets/tree-sitter/loam-runtime.js= ESM loader
- 通过 =:head= 注入 CSS、runtime loader 和 =assets/loam-client.js=

Tree-sitter 浏览器端模块位于：

#+begin_example
src/loam/highlight/treesitter/client.cljs
#+end_example

它由通用入口 =loam.client= 引入，并通过 =shadow-cljs= 编译到：

#+begin_example
public/assets/loam-client.js
#+end_example

Tree-sitter runtime、语言 WASM、query、license、manifest 文件由 Guix 构建，再同步到：

#+begin_example
public/assets/tree-sitter/tree-sitter.js
public/assets/tree-sitter/tree-sitter.wasm
public/assets/tree-sitter/languages/tree-sitter-clojure.wasm
public/assets/tree-sitter/languages/tree-sitter-javascript.wasm
public/assets/tree-sitter/languages/tree-sitter-typescript.wasm
public/assets/tree-sitter/languages/tree-sitter-python.wasm
public/assets/tree-sitter/languages/tree-sitter-scala.wasm
public/assets/tree-sitter/queries/*/highlights.scm
public/assets/tree-sitter/licenses/*.txt
public/assets/tree-sitter/manifest.edn
public/assets/tree-sitter/manifest.json
#+end_example

Runtime loader 是一个小的 ESM 文件，默认内容类似：

#+begin_src javascript
import * as runtime from "./tree-sitter.js";
globalThis["LoamTreeSitter"] = runtime;
globalThis.dispatchEvent(new CustomEvent("loam:tree-sitter-runtime", {detail: runtime}));
#+end_src

这样 =assets/loam-client.js= 不需要使用 =Function(...)= 或动态 =import(...)=，对严格 CSP 更友好。注意：如果站点启用了非常严格的 CSP，WASM 编译本身可能仍需要浏览器支持的 WASM 相关策略，例如 =wasm-unsafe-eval=；这取决于浏览器和部署环境。

自定义 runtime：

#+begin_src clojure
(loam/create-system
 {:highlight {:provider :treesitter
              :runtime "https://cdn.example.com/tree-sitter.js"
              :runtime-global "MyTreeSitter"}})
#+end_src

自定义语言：

#+begin_src clojure
(loam/create-system
 {:highlight {:provider :treesitter
              :languages
              {:rust {:aliases ["rs"]
                      :wasm "/assets/tree-sitter/languages/tree-sitter-rust.wasm"
                      :query "/assets/tree-sitter/queries/rust/highlights.scm"}}}})
#+end_src

替换或新增 grammar 时，要保证 =web-tree-sitter= runtime 和语言 WASM 的 ABI 版本兼容。Loam 的默认方案是修改 =guix/loam/tree-sitter-grammars.scm= 这一份 registry，用固定 repo/commit/hash 描述 grammar；Guix package 和资产 builder 都读取它，然后运行：

#+begin_src bash
guix build -f guix/loam-tree-sitter-assets.scm
npm run copy-tree-sitter-assets
npm run smoke-tree-sitter-assets
#+end_src

启用 Tree-sitter 的完整构建顺序通常是：

#+begin_src bash
npm run copy-tree-sitter-assets
npm run client:release
bb build --edn-dir /path/to/edn --output-dir build/site
#+end_src

* Shiki 高亮

Shiki 是另一种高亮提供方案。它基于 TextMate grammar 和主题，更偏展示效果，适合更强调主题一致性的场景。

默认系统已经启用 Shiki。你也可以用 =:highlight= 显式配置 Shiki provider：

#+begin_src clojure
(require '[loam.defaults :as loam])

(def system
  (loam/create-system
   {:highlight
    {:provider :shiki
     :theme "github-dark"
     :languages ["clojure" "javascript" "typescript" "python"]}}))
#+end_src

Shiki 高亮由一个 provider extension 实现，并会：

- 覆盖 =:src-block= 渲染，添加 =data-loam-shiki= 标记
- 写入 =assets/loam-shiki.css=
- 写入 =assets/loam-shiki.js=
- 通过 =:head= 注入 CSS 和 Shiki 客户端脚本

Shiki 客户端当前默认从 ESM import specifier 加载：

#+begin_example
https://esm.sh/shiki@4.0.2
#+end_example

这样做的好处是简单、可切换、易于和 npm 生态对接。以后如果你想改成完全本地化 bundle，只需要把 =:import= 指向本地 ESM 文件，或者再加一层构建脚本把 Shiki 打包到 =public/=。

* 示例：覆盖段落渲染

#+begin_src clojure
(require '[loam.render])

(def paragraph-extension
  {:id :example/paragraph
   :extends
   {:renderers
    {:paragraph (fn [ctx node]
                  [[:p.lead (loam.render/text-content node)]])}}})
#+end_src

这个 extension 只向 =:renderers= 贡献 =:paragraph=。其他节点仍使用默认渲染器。

* 示例：添加索引数据

Indexer 接收当前 index 和 documents，返回新的 index。

#+begin_src clojure
(require '[loam.ast])

(def word-count-extension
  {:id :example/word-count
   :extends
   {:indexers
    [(fn [idx documents]
       (assoc idx :word-count
              (reduce +
                      (map #(count (re-seq #"\\S+" (loam.ast/text (:ast %))))
                           documents))))]}})
#+end_src

生成后的数据会保存在构建上下文中，layout 或 hook 可以读取它。

* 示例：替换页面布局

#+begin_src clojure
(require '[loam.render])

(def layout-extension
  {:id :example/layout
   :extends
   {:layouts
    {:page (fn [ctx document]
             [:html
              [:body
               [:main
                (loam.render/render-document ctx (:ast document))]]])}}})
#+end_src

默认主题提供 =:home= 和 =:page= 两个 layout。如果只替换 =:page=，首页仍然可以使用默认布局。

* 配置文件

Loam 支持 EDN 构建配置文件。示例见 =loam.edn.example=：

#+begin_src clojure
{:edn-dir "build/edn"
 :output-dir "build/site"
 :url-prefix "/notes/"
 :public-dir "public"
 :site-title "Loam"
 :highlight {:provider :shiki
             :theme "github-dark"
             :languages ["clojure" "javascript" "typescript" "python"]}}
#+end_src

运行：

#+begin_src bash
bb build --config loam.edn
npm run build -- --config loam.edn
#+end_src

配置文件里的相对路径（=:edn-dir=、=:output-dir=、=:public-dir=）会按配置文件所在目录解析。命令行参数会覆盖配置文件值：

#+begin_src bash
bb build --config loam.edn --output-dir /tmp/site
#+end_src

注意：EDN 配置适合声明普通数据，例如路径、标题、=:highlight= provider 配置。需要函数值的自定义 extension 仍应在 Clojure 代码里组合 system，而不是塞进 EDN 文件。

* 直接调用构建 API

除了 CLI，也可以在 Clojure 中直接调用：

#+begin_src clojure
(require '[loam.site :as site])

(site/build-site!
 {:edn-dir "build/edn"
  :output-dir "build/site"
  :url-prefix "/notes/"
  :public-dir "public"
  :site-title "My Notes"})
#+end_src

常用选项：

| 选项 | 默认值 | 说明 |
|------+--------+------|
| =:edn-dir= | 必填 | EDN 文档目录 |
| =:output-dir= | 必填 | 静态站点输出目录 |
| =:url-prefix= | ="/notes/"= | 文档页面 URL 前缀 |
| =:public-dir= | ="public"= | 用户静态资产目录 |
| =:site-title= | ="Loam"= | 默认主题显示的网站标题 |
| =:highlight= | =:shiki= | 高亮 provider；可选 =:treesitter=、=:shiki=、=:none=、provider 配置 map 或高亮 extension map |
| =:extensions= | =nil= | 追加安装的 extension；EDN 配置中通常不写函数型 extension |

* 排障

** 页面没有样式或脚本

确认构建命令使用了 =npm run build=，而不是只运行 =bb build=。如果直接运行 =bb build=，默认 Shiki 资产由 extension 写入输出目录；只有 =loam-client.js= 这类编译型客户端资产需要先执行：

#+begin_src bash
npm run prepare-assets
#+end_src

** Tree-sitter 高亮不生效

先确认系统配置里启用了 ={:highlight :treesitter}= 或 ={:highlight {:provider :treesitter ...}}=。然后检查输出目录是否包含：

#+begin_example
assets/loam-client.js
assets/tree-sitter/loam-runtime.js
assets/tree-sitter/tree-sitter.js
assets/tree-sitter/tree-sitter.wasm
assets/tree-sitter/languages/tree-sitter-clojure.wasm
assets/tree-sitter/queries/clojure/highlights.scm
#+end_example

如果缺少 =assets/tree-sitter/**=，先运行：

#+begin_src bash
npm run copy-tree-sitter-assets
npm run smoke-tree-sitter-assets
#+end_src

还要确认页面是通过 HTTP 服务访问，而不是 =file://=。

** 浏览器报 WASM 或 fetch 错误

常见原因：

- 直接打开本地 HTML 文件，浏览器阻止 fetch/WASM
- 部署服务没有正确提供 =.wasm= 文件
- CDN 或子路径部署导致资产路径不匹配
- Tree-sitter runtime 和 grammar WASM ABI 不兼容

** 自定义语言没有高亮

确认 =:languages= 里语言名、alias、WASM 路径和 query 路径都正确。Loam 会先用 src block 的语言名查找语言配置，再查找 aliases。

** 搜索没有结果

检查输出目录中的 =search-index.json=。默认搜索只索引 Loam 从 AST 中提取到的文本内容；如果自定义节点没有提供可提取文本，可能需要扩展 =loam.ast/text= 或添加自己的索引器。

* 当前边界

Loam 现在聚焦静态知识库和文档站点生成，不负责：

- Org 解析本身；这由 =ox-edn= 负责
- 客户端路由框架
- 大型前端应用状态管理
- 服务端动态查询
- 全文搜索引擎后端

这些能力可以通过扩展或外部系统接入，但不应该进入核心。
